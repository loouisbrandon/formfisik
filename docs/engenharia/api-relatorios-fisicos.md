# API de relatórios físicos

Todas as operações exigem sessão opaca vigente, profissional com e-mail confirmado e autorização comercial no servidor. Respostas privadas/no-store. Nenhum JWT, URL pública, chave de objeto ou segredo. Erros 401 sessão, 403 permissão/origem, 404 recurso alheio/ausente/expirado, 400 configuração, 409 alteração concorrente, 422 limite de conteúdo, 429 abuso, 503 dependência indisponível.

- `GET /api/students/:id/physical-reports`: range=all|30|90|6m|12m|custom, from/to ISO civis, page >=1. Retorna nome, active/total, itens de avaliações (id/date/state/version), anchors first/latest/previous e photosConfigured. Página de 20, ordem recente; limite é rejeitado, não carregado inteiro na interface. Página vazia mantém page solicitado, items vazio e total/pages calculados (pages mínimo1), sem carregar registros ocultos no frontend.
- `GET /api/students/:id/physical-reports/photos`: mesmos parâmetros + date, position e recordId opcionais. Página de 12, metadados privados, nunca bytes/chaves. Sem storage: configured=false, lista vazia e páginas=1.
- `POST /api/students/:id/physical-reports`: origem igual à aplicação; JSON estrito até 16KiB. `layout` compact|premium; `period` {range,from,to}; `content` com os 11 booleanos de `contentLabels`; `measureMetrics` array único de chaves da 012; `compare` {mode:first|previous|manual,from:UUID|null,to:UUID|null}; `photoIds` array único até12; `photoConsent` null ou {purpose:shareable_physical_report,authorization:{source,obtainedOn,subject:adult|guardian,guardian,attested:true}}. Pelo menos um conteúdo. Datas custom válidas e ordenadas. IDs de comparação manual diferentes. Fotos exigem seleção/consentimento; fotos desmarcadas exigem seleção vazia/consentimento null. Retorna 201 {id,filename,expiresInSeconds:900,assessmentCount,comparison:{from,to}|null}.
- `GET /api/physical-reports/:id`: PDF inline; `?download=1` muda somente disposição para attachment. Mesmos bytes, nome genérico sem nome privado do aluno. Headers private/no-store, nosniff, referrer-policy no-referrer. Revalida proprietário, assinatura, validade, vínculos fotográficos e autorização.
- `DELETE /api/physical-reports/:id`: mesma origem; remove somente relatório próprio, com dependências em cascata. Resposta idempotente 200.

Rate limiting no servidor por usuário/operação: geração 5/minuto; demais 120/minuto. Filtragem por proprietário sempre no SQL, inclusive seleção manual e fotografias. UUID/configurações estritas; erro não expõe valores privados. Manifest, declaração e PDF não são devolvidos em JSON de listagens. Não registrar corpo, fotos ou tokens em logs.

Contratos executáveis: `src/modules/physical-reports/schema.ts`, `src/server/physical-reports/handlers.ts`. Reutiliza `GET/PUT /api/professional/presentation` e leitura privada de imagens da 013, sem duplicar contratos.
